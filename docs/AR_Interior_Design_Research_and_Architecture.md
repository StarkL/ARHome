## 1. 需求背景与核心价值

传统毛坯房量房与硬软装设计面临严重的“**空间尺度认知失真**”：
- **物理现场无参照物**：空置的水泥毛坯房在人眼中往往显得“比实际更小”（空间空旷导致的透视错觉）。业主常因担心放不下床或柜子而保守缩减尺寸，或反之购买过大导致入户无法通行。
- **2D 图纸无法感知动线**：CAD 平面布置图无法直观体验走过床侧、沙发与茶几之间的真实躯体压迫感与通过净宽。
- **改造成本不可逆**：一旦实物家具进场再发现尺寸冲突、遮挡插座开关或动线狭窄，退换货与定制更改成本极高。

**AR 1:1 现场试摆的核心价值**：
1. **真实物理场域叠加**：在毛坯房真实毛坯墙面、采光窗前，直接投射精确到毫米的虚拟 3D 家具。
2. **真人体感漫游走动**：佩戴眼镜自由步入卧室、客厅，以 1.6m~1.8m 真实人眼视角评估天花板净高、视线开阔度、床边过道宽裕度。
3. **即时决策与协同改案**：现场一键替换单人床/1.8米大床，滑动调整布局，自动提示通道是否达标（>600mm/800mm），生成采购清单。

### 2.2 开源技术框架与底层组件

1. **WebXR Device API (W3C 标准)**
   - **核心模块**：`immersive-ar`（沉浸式 AR 会话）、`hit-test`（光线碰撞检测）、`plane-detection`（平面检测识别地板与墙面）、`depth-sensing`（硬件深度图）。
   - **现状**：Meta Quest 3 内置浏览器已全面支持；Android Chrome 配合 ARCore 支持手机透视；visionOS Safari 暂未开放 AR 摄像头原始数据（出于隐私考虑），但支持全景 VR 空间。
   - **适用性**：跨平台 Web 模拟与轻量化落地首选，避免各品牌眼镜开发原生 App 的高门槛。

2. **渲染与交互引擎：Three.js / React Three Fiber / Babylon.js**
   - **Three.js**：最成熟、轻量、插件丰富的 WebGL/WebGPU 3D 引擎。
   - **GLTF/GLB 标准**：支持 PBR 材质（金属度、粗糙度、法线贴图），Draco 几何压缩，适合快速加载大批量 1:1 精确尺寸家具模型。
   - **Gizmo 交互**：TransformControls 支持旋转、位移、贴地吸附，满足摆放调整需求。

3. **空间定位与建图 (SLAM) 开源方案**
   - **ORB-SLAM3 / OpenVSLAM**：支持单目、双目、双目惯导（Visual-Inertial SLAM），多地图系统。若采用定制硬件或工控 AR，可作为底层算法底座。
   - **RTAB-Map (Real-Time Appearance-Based Mapping)**：支持 RGB-D 深度相机（如 RealSense、Orbbec）进行毛坯房 3D 点云与网格实时构建。
   - **Apple RoomPlan Framework**：虽闭源但为 iOS 原生免费 SDK，可直接导出包含真实尺寸的结构几何体（USDZ 格式）。

4. **3D Gaussian Splatting (3DGS) & NeRF**
   - 新兴的空间数字化技术，拍摄毛坯房视频即可 5 分钟在云端生成超逼真 3D 场景，可作为 Web 模拟器的超高清背景环境。

## 3. 核心技术难点与攻关策略（毛坯房特性）

毛坯房现场环境与普通精装房相比，有其极其苛刻的特殊性：

```
┌─────────────────────────────────────────────────────────────┐
│                   毛坯房特定物理挑战与技术对策                │
├─────────────────────────────────────────────────────────────┤
│ 1. 弱纹理/纯灰泥地面墙面  ──> 惯性IMU融合 + 深度相机/主动红外点阵 │
│ 2. 强日光/无窗帘刺眼光照  ──> 自动白平衡 + 电致变色镜片(OST) / VST │
│ 3. 空间无参照物尺度错觉  ──> 1:1 动态三维尺寸线标注 + 地面走道红绿线 │
│ 4. 立柱/承重墙/门洞穿模  ──> 虚实遮挡着色器 (Depth Occlusion Mask) │
│ 5. 施工粉尘/行动不便    ──> 手机作为手持控制器 + 手势触控双冗余    │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 弱纹理水泥地面的 SLAM 空间定位与漂移
- **痛点**：普通基于纯视觉特征点匹配（Feature-based VIO）在光滑水泥平整地面上几乎找不到足够的角点，极易发生“漂移（Drift）”或虚拟家具“贴地打滑”。
- **对策**：
  1. 选用具备**主动红外结构光 / ToF / LiDAR 深度传感器**的硬件（如 Quest 3 或 iPhone LiDAR），不受表面视觉纹理限制；
  2. 结合物理空间固定参照物（例如门框、窗户横梁、电箱盒边缘具有极高对比度的结构轮廓）作为空间锚点（Spatial Anchors）。

### 3.2 1:1 绝对物理尺度的精准标定（毫米级公差）
- **痛点**：如果虚拟 1.8 米大床在眼镜里实际被缩放成了 1.72 米，或者由于摄像机焦距标定误差导致 1 米距离测量出现 5 厘米偏差，将直接导致软装决策失误。
- **对策**：
  1. **模型元数据标准单位**：所有模型资产以米（Meter）为基准单位，顶点坐标严格按出厂物理长宽高建模，杜绝无规则缩放。
  2. **基准面矫正**：通过射线检测（Raycasting）直接吸附物理地面，并在摆放时实时显示“三维工程尺寸线与毫米国标数值”（例如：`长 1800mm × 宽 2000mm × 高 950mm`）。

### 3.3 物理墙体/柱子与虚拟家具的深度遮挡（Occlusion）
- **痛点**：当家具推入墙角或被承重柱遮挡时，若没有遮挡剔除，虚拟家具会“漂浮在柱子表面前”，破坏空间透视感。
- **对策**：
  1. 利用设备的实时网格重建（Spatial Meshing）；
  2. 在着色器中渲染一层只写入深度缓冲区、不写入颜色缓冲区的隐形网格（`colorWrite = false, depthWrite = true`），物理墙体即可完美自然遮挡被挡住的虚拟家具部位。

### 3.4 虚实光影融合与地面接触阴影（Contact Shadows）
- **痛点**：没有阴影的家具会显得“浮空”。毛坯房水泥地面粗糙且吸光，需要真实的接触阴影。
- **对策**：
  1. 采用不可见的阴影接收面（`ShadowReceiver Ground`），仅接收环境光与平行光阴影；
  2. 动态调节光源角度匹配毛坯房真实落地窗的朝向（例如南向大阳台的日光斜射），让虚拟家具的影子顺着窗户采光方向投射在水泥地上。

### 3.5 动线安全与人体工程学预警（Clearance Safety）
- **痛点**：家具摆放后，过道是否满足人体通行规范？
- **对策**：
  - 国标人体工程学通行净宽规范：
    - 主通行过道：≥ 800mm ~ 900mm
    - 床侧/床尾通道：≥ 600mm
    - 柜门/抽屉开启余量：≥ 700mm
  - 系统在家具周围自动生成可折叠的“安全动态检测环”，当与墙壁或其他家具间距不足 600mm 时，地面自动泛红警告并显示实际剩余净宽。

## 4. 硬件选型方案与对比矩阵

当前实现毛坯房沉浸式实景试摆，业界主要存在三大硬件技术路径：

```
                    ┌─────────────────────────┐
                    │    毛坯房 AR 家居试摆    │
                    │       硬件路径选择      │
                    └────────────┬────────────┘
                                 │
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
  【路径一：VST 穿透头显】   【路径二：OST 光学AR眼镜】    【路径三：手机/LiDAR过渡】
  代表：Meta Quest 3       代表：XREAL Air 2 Ultra    代表：iPhone/iPad Pro
  优势：全不透明遮挡/真黑位   优势：极轻便(<90g)/透气     优势：零新增硬件成本
  劣势：头戴略重(500g)      劣势：强光下透明/需暗镜     劣势：小屏非沉浸漫游
```

### 4.1 详细参数与适用性比对

| 对比维度 | 路径一：VST 视频透视 (Meta Quest 3) | 路径二：OST 光学透视 (XREAL / Rokid) | 路径三：手机/iPad Pro LiDAR |
| :--- | :--- | :--- | :--- |
| **典型代表机型** | **Meta Quest 3 (128G/512G)** | **XREAL Air 2 Ultra + 终端** | **iPhone 15/16 Pro / iPad Pro** |
| **显示原理** | 外置双目彩色摄像头抓拍环境，屏幕合成显示 (Video See-Through) | 衍射光波导/Birdbath 透镜直接透视真实物理光线 (Optical See-Through) | 手机视网膜屏幕显示摄像头画面 |
| **视野视场角 (FOV)** | **~110° 水平**（近乎全视野覆盖） | **~52° 对角线**（类似 3 米外百寸画面）| 受限手机屏幕大小 |
| **黑色与材质呈现** | **完美渲染**（纯黑就是黑，实体家具 100% 不透明） | **黑色为透明**（在毛坯房强光下，深色皮革或深木纹会有半透明感） | 完美渲染 |
| **遮挡真实度** | 依靠深度网格实时扣像，虚实遮挡极佳 | 需要额外光阀/遮光片，物理遮挡难度大 | 依靠 LiDAR 深度遮挡（屏幕内） |
| **设备重量** | 约 515 克（需配舒适头戴） | 约 80~95 克（普通太阳镜手感） | 手持约 200 克 |
| **毛坯房行动安全** | 彩色透视延迟 <12ms，安全可走动 | 直接肉眼看现场，极其安全自然 | 边走边看屏幕，需注意脚下 |
| **WebXR / 开发门槛**| **极低**（Meta 浏览器原生 WebXR 支持）| 需使用 NRSDK / Rokid SDK 原生开发 | Safari/Chrome WebXR 需适配 |
| **参考采购单价** | **约 3,400 ~ 4,200 RMB** | **约 4,500 ~ 6,500 RMB (含计算盒)** | **已有设备 0 元 / 采购约 7,000+** |

### 4.2 最终落地选型建议

- **阶段一（当前研发与模拟）**：**纯 Web 3D 浏览器模拟器**（零硬件投入，鼠标/键盘第一人称走动，全套尺寸标注与摆放系统）。
- **阶段二（实物进场最具性价比首选）**：**Meta Quest 3**。
  - **原因**：支持真正的 1:1 固体家具显示（不透光），110° 大视野带来极其震撼的真实空间感；自带 WebXR 支持，研发的 Web 系统几乎无需重写即可直接投射到 Quest 浏览器中运行；单机 3000 多元，成本极低。
- **阶段三（未来商业化交付给普通业主）**：**分体式轻量 AR 眼镜（如 XREAL Ultra / Rokid）**，配专属手机 App，业务员随包携带方便。

### 6.2 双端协同交互范式设计

在毛坯房实地操作中，全靠在眼镜前挥动手势挑选几百款家具有时会造成手臂疲劳。业界最佳交互范式为：**“手机/平板选款 + 眼镜主视沉浸”**。
1. **手机端作为超级遥控器**：在手机屏幕上浏览床、沙发的高清材质、价格、品牌、选定 1.8m 或 2.0m 规格；
2. **一键“投送进房间”**：点击“放置到眼前”，通过局域网/WebRTC/WebSocket 广播给佩戴者的 AR 眼镜；
3. **眼镜端空间微调与走动**：佩戴者眼见家具落在地面上，可直接用视线或手势轻微推移靠墙，然后**迈开双腿在毛坯房中真实绕床一周**，亲身体会床头离窗户的距离是否压抑、起夜下床通道是否宽敞。

## 8. 结论与第一阶段 Web 模拟系统交付

本调研为“毛坯房 1:1 AR 眼镜软装试摆”确立了最务实、高性价比的技术路径：
